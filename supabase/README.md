# Supabase & PostgreSQL Архитектура (SmartRent)

В данной директории содержатся схемы и миграции базы данных Supabase для платформы **SmartRent**.

## 1. Структура БД

- **`properties`**: Объекты недвижимости (квартиры). Связаны с пользователями (`owner_id -> auth.users.id`).
- **`devices`**: Устройства, привязанные к объектам (`(property_id, id)` — составной первичный ключ). Поддерживаемые типы: `lock`, `relay`, `valve`, `climate`, `sensor`.
- **`device_logs`**: Поток телеметрии и событий. Ретеншн логов — 90 дней (автоматическая очистка через `pg_cron`).
- **`property_pins`**: Зашифрованные PIN-коды для смарт-замков (TTLock). PIN-коды никогда не сохраняются в открытом виде.
- **`audit_logs`**: Журнал аудита действий физической безопасности и изменений доступа.

## 2. Row Level Security (RLS)

На всех таблицах включен RLS:
- Пользователи имеют доступ **только** к объектам, устройствам, пинам и логам тех квартир, владельцами которых они являются (`owner_id = auth.uid()`).
- Доступ из Backend API осуществляется с передачей JWT токена пользователя (`auth.uid()`), гарантируя мультитенантную изоляцию на уровне СУБД.
- Фоновый MQTT Worker и системные сервисы могут использовать `service_role` ключ исключительно для фоновой записи телеметрии в `device_logs`.

## 3. Автоматическая очистка логов (`pg_cron`)

Ежедневно в 03:00 UTC выполняется удаление записей старше 90 дней:
```sql
DELETE FROM device_logs WHERE created_at < now() - INTERVAL '90 days';
```

## 4. Применение миграций

### Через Supabase CLI:
```bash
supabase db push
# или для локальной разработки
supabase start
supabase migration up
```

### Через Supabase Web Dashboard:
Скопировать содержимое файла `migrations/20260901000000_initial_schema.sql` в раздел **SQL Editor** панели Supabase и нажать кнопку **Run**.
