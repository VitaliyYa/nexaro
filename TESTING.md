# Стратегия тестирования и Чек-листы (TESTING.md)

В данном документе описан подход к обеспечению качества (QA) платформы SmartRent.

## 1. Автоматизированное тестирование

### Backend (Pytest)
- [x] Тесты роутов API FastAPI (аутентификация, валидация прав доступа через JWT от Supabase).
- [x] Unit-тесты для MQTT Worker'а: корректный парсинг входящих Payload из `state` топиков.
- [x] Тестирование изоляции мультитенантности на уровне БД (проверка работоспособности RLS политик).
- [x] Тестирование шифрования PIN-кодов (AES/Fernet) и аудита операций в `audit_logs`.
- [x] Тестирование Mosquitto go-auth HTTP вебхуков (`/user`, `/superuser`, `/acl`).
- [x] Тестирование диспетчера команд устройств в MQTT (`/set` топики, QoS 1, retain: false).
- [x] **Live API & Integration Tests (на работающем сервере и брокере):**
  - Проверка работоспособности живого сервера и подключения к брокеру: `GET /health`.
  - Проверка аутентификации пользователя Mosquitto: `POST /api/v1/auth/mqtt/user` (валидный пароль из `.env`, неверный пароль, form-urlencoded).
  - Проверка прав суперпользователя: `POST /api/v1/auth/mqtt/superuser` (воркер — 200 OK, посторонний — 403 Forbidden).
  - Проверка изоляции топиков: `POST /api/v1/auth/mqtt/acl` (воркеру разрешены `properties/+/+/+/set`, запрещены чужие префиксы; неизвестным узлам доступ запрещен).
  - Запуск через Pytest: `uv run pytest -m integration`
  - Запуск через CLI-скрипт: `uv run python scripts/test_live_api.py`


### Frontend (Playwright)

## 2. Ручное и Интеграционное тестирование (HAOS Bridge)

Для проверки корректной работы Edge-узлов (HAOS) с облаком:
- [ ] **Топик `set`:** Отправить тестовую команду через MQTT Explorer или Backend в топик `.../set` -> убедиться, что HAOS принял команду и активировал соответствующую службу.
- [ ] **Топик `state`:** Физически изменить состояние устройства (например, нажать кнопку на датчике) -> убедиться, что HAOS опубликовал сообщение в топик `.../state` с правильным Payload.
- [ ] **Retained Messages:** Отключить и заново подключить MQTT Explorer к брокеру -> проверить, что статус устройств сразу загружается из `retained` сообщений без дополнительных запросов.
- [ ] **Отсутствие сети:** Имитировать отключение интернета на Edge-узле -> вызвать срабатывание датчика протечки -> убедиться, что кран перекрывается локально.

## 3. Нагрузочное тестирование (В перспективе)
- [ ] Проверка брокера Mosquitto на количество одновременных подключений (1000+ Edge-узлов).
- [ ] Проверка Backend MQTT Worker'а на скорость обработки очереди сообщений от большого количества квартир.
