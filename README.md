# SmartRent - B2B SaaS for PropTech & Short-term Rentals

SmartRent — это B2B SaaS платформа, интегрированная с IoT-инфраструктурой. Она разработана для автоматизации управления объектами краткосрочной аренды (Airbnb, Booking) для property-менеджеров и инвесторов недвижимости.

## Ключевая ценность (Core Value)

- **Бесключевой удаленный Check-in:** Управление смарт-замками (TTLock) и генерация PIN-кодов вручную или на основе TOTP.
- **Энергоэффективность:** Автоматическое отключение кондиционеров (AC) при выезде гостей или при длительно открытых окнах.
- **Защита активов:** Автономное локальное перекрытие воды при срабатывании датчиков протечки, независимо от наличия интернета.

## Архитектура

Система построена на распределенной микросервисной архитектуре, где каждая квартира работает как автономный Edge-узел, общающийся с облаком через MQTT.

- **Edge Layer (Апартаменты):** 
  - **Контроллер:** Home Assistant OS (HAOS) на Raspberry Pi 4 / HA Green в режиме headless (невидимый для гостя исполнитель).
  - **Оборудование:** Смарт-замок TTLock, периферия Zigbee (Aqara/Tuya Hub, IR-бластеры, датчики протечки, приводы кранов, датчики открытия окон/дверей).
- **Transport Layer (Связь):** 
  - Eclipse Mosquitto MQTT брокер на центральном VPS.
  - Двусторонний защищенный обмен (MQTTS, Port 8883, Let's Encrypt TLS).
  - HAOS на объектах выступает инициатором соединения (исходящий трафик), что не требует "белых" IP и проброса портов на роутерах квартир.
- **Cloud Backend:** 
  - Python 3.14 (менеджер пакетов `uv`).
  - Фреймворк FastAPI.
  - Paho-MQTT для подписки на топики, отправки команд и фильтрации телеметрии.
- **Data Layer (БД и Авторизация):** 
  - Supabase (PostgreSQL) с использованием GoTrue Auth.
  - Строгая изоляция данных (Row Level Security - RLS) по ролям: Superadmin, Owner, Property Manager.
  - Автоматическая ротация логов (хранение 30-90 дней) с использованием `pg_cron` или встроенных настроек в Supabase.
- **Frontend:** 
  - Progressive Web App (PWA) на React/Vue.
  - UI-паттерн `optimistic: false`: элементы интерфейса меняют состояние только после получения подтверждения (retained state) от физического устройства через MQTT.

## 🛠 Технологический стек и Инфраструктура

- **Оркестрация:** Docker, Docker Compose
- **Брокер сообщений:** Eclipse Mosquitto
- **Backend:** Python, FastAPI
- **База данных:** PostgreSQL (Supabase)
- **QA & Тестирование:** Pytest, Python Playwright (E2E), Allure Reports
- **CI/CD:** GitHub Actions (запуск тестов, сборка и публикация Docker-образов)

## 🚀 Основные принципы работы (Паттерны)

1. **Разделение топиков Command / State:**
   - Команды отправляются в топик `<property_id>/<device_id>/set`.
   - Фактическое состояние публикуется устройством в топик `<property_id>/<device_id>/state` с флагом `retain: true`.
2. **Точка истины на Edge:** Если пропадает интернет, базовые автоматизации (например, перекрытие воды при протечке) продолжают работать локально в HAOS.
3. **Безопасность брокера:** Каждому Edge-узлу (квартире) и Backend-сервису выдаются изолированные учетные данные с жестко ограниченными ACL (доступ только к своему пространству топиков).
